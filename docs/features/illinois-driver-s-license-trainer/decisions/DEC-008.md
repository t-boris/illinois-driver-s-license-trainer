## Context

REQ-003 requires a recorded bilingual review and a manual-section reference for every content item, but DEC-004 rules out a backend and no decision says where content lives or how the rule is enforced.

## Alternatives

1. Structured content files in the repository with review metadata, validated by a build step
2. External CMS or spreadsheet with review tracked there and exported at build time

## Decision

All learning content (lessons, questions, answers, explanations) is versioned in the application repository as structured files. Each item carries metadata: the Rules of the Road section reference, the manual version/date it was verified against, and review records for Russian and for English (reviewer, date). A build-time validation step fails the build when any item lacks the reference or either review record, so unreviewed content can never be deployed. Reviews are performed by the product owner or a reviewer designated by them, via the normal pull-request flow. Concrete file format and schema are the implementer's choice.

## Reason

No backend or extra tooling is needed, matches the Vercel static deployment, git history provides the audit trail, and the build gate makes the REQ-003 criteria mechanically enforceable.

## Consequences

Content authors work through the repository (PRs). A validation script and content schema become part of the project. Re-check after a manual update is done by comparing the stored manual version with the current one.
