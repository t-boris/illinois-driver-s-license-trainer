## Context

Progress tracking requires storing data; the team had to decide between no accounts, optional sign-in, or mandatory registration.

## Alternatives

1. B — optional sign-in (e.g. Google) for cross-device sync
2. C — mandatory registration

## Decision

v1 has no accounts and no backend user data. Progress (topic results, simulation history, readiness) is stored locally in the user's browser on that device.

## Reason

Zero entry barrier, no personal data processing, no backend — fits a fun, lightweight product. Optional sign-in for sync is a natural later step.

## Consequences

Progress is lost when the user changes device or clears browser storage; the app must state this clearly and offer a way to reset progress. No authentication, no database of users in v1.
