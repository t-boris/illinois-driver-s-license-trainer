## Context

DEC-027 chose the OpenAI image API and left access to the owner. The owner supplied the key through the clipboard and expects images to be cached rather than paid for twice.

## Alternatives

1. Regenerate images on every run (rejected: repeated API cost)
2. Generate images at build time on Vercel (rejected: cost and time on every deploy, and the key would live in the build environment)

## Decision

The assistant read the key from the clipboard once and stored it in a git-ignored `.env.local` (never printed, never committed). Images are generated by `scripts/generate-images.mjs` into `public/images/<content id>.webp`, committed to the repository, and never regenerated when the file already exists; an existing file is only re-attached to its content item without any API call. The deployed site serves `/images/*` with `Cache-Control: public, max-age=86400, stale-while-revalidate=604800` and `/fonts/*` with a one-year immutable cache (`vercel.json`); hashed build assets use Vercel's default immutable caching. To replace an image, delete its file and run the script again. Amends DEC-027.

## Reason

Pays once per image, keeps builds fast and the key out of the repository and the deployment.

## Consequences

All 145 images were generated and reviewed on contact sheets. The first pass showed that the phrase "Illinois setting" made the model draw state boards, traffic lights and a railroad crossing with text; the style prefix now says "Midwestern American setting" with an explicit no-signboards rule, the prompt lint ignores negated clauses, and the 34 affected images were regenerated and re-reviewed. Only incidental lettering remains (for example SCHOOL BUS on a bus, an office label); no road sign or signal is AI-drawn. The owner should still look at the images.

Images ship with the app as static files. The owner keeps responsibility for the key and its cost. If the key is rotated, `.env.local` is updated.
